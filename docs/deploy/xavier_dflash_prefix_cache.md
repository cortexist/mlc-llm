# DFlash prefix reuse on Xavier

This records the conservative recycling profile. The later
[protected service-prefix profile](xavier_service_prefix.md) adds safe independent
copies, two recent conversations and server-owned guidance. Its tool adapter also
reports standard cache-read usage to clients.

DFlash keeps projected draft-context features for as long as the corresponding
cached target KV sequence. Reusing a prefix rewinds an idle sequence and truncates
its draft features to the same token boundary. Eviction, cancellation and reset
remove the associated state; misses discard stale internal-ID contents.

DFlash defaults to a recycling-only radix policy. It never forks a shared prefix: a
match against an active sequence becomes a cache miss. In this Gemma4 runtime,
per-layer sliding-window attention over forked KV depths changed generated
benchmark numbers. The problem reproduced with the original attention kernels
and with draft proposals disabled; aligning reuse to chunk boundaries did not
resolve it. Rewinding the idle sequence avoids that path and passed the long
conversation replay. Other speculative modes retain their existing cache policy.

The validated single-request Xavier service enables
`MLC_NEMOTRON_PREFIX_CACHE=radix` and retains one recycled sequence. The code
keeps `disable` as its default for opt-in deployment and rollback. This needs a
runtime rebuild, without reconverting weights or rebuilding model libraries.
Retaining draft features adds memory proportional to the cached context.

## Short GPU comparison

Nemotron 3.5 Bolt E4B q4f16_1 on AGX Xavier 32 GB, DFlash with two proposals,
16K capacity, 512-token prefill chunks, one request at a time. Both modes ran the
same input IDs in the same order, with 24 forced greedy output tokens per case.
These are individual latency samples, not medians or a sustained-load test.

| Case | Uncached total (s) | Cached total (s) | Tokens actually prefilled with cache |
| --- | ---: | ---: | ---: |
| Repeat 910-token prompt | 2.865 | 0.945 | 1 |
| Append 32 tokens | 3.202 | 1.260 | 32 |
| Reuse shorter 448-token prefix | 1.439 | 0.784 | 1 |
| Different 161-token prompt | 1.339 | 1.316 | 157 |
| Original prompt after eviction | 2.867 | 2.902 | 906 |
| Original prompt after cancellation | 2.894 | 0.948 | 1 |
| Original prompt after reset | 2.857 | 2.895 | 910 |

All eight cases, including the initial cold request, produced identical text
between cached and uncached DFlash. A repeated prompt leaves one token to compute
its next-token logits. The different prompts share four initial template tokens.
This checks short continuations; it does not establish general speculative/plain
equivalence or qualify full-context memory and sustained stability.

Raw timing fields and processed-token counts are in
[`dflash-prefix-summary.json`](../benchmarks/xavier/dflash-prefix-summary.json).

## Long conversation and Pi

The exact 4,346-token Pi continuation that failed with shared-prefix forks now
produces the same 160-token response text as the uncached run. It prefills 1,876 tokens;
time to first token improves from 18.97 to 11.00 seconds, and total time from
24.16 to 16.16 seconds. These are matched single samples.

In a full Pi conversation:

| Turn | Time (s) | Output tokens |
| --- | ---: | ---: |
| First workspace benchmark question | 30.36 | 386 |
| Repeat that question | 26.49 | 433 |
| Switch to a general France question | 21.17 | 10 |
| General Git question | 6.39 | 120 |
| General France question again | 0.85 | 10 |

The earlier uncached repeated workspace question took 32.56 seconds for 386
output tokens. The full cached response preserves every benchmark value but has
additional wording, so this is not a fixed-output throughput comparison. The Git
answer still over-explained beyond the requested operation; this change does not
qualify general model quality. No model-issued tool calls occurred in these five
turns. Separate HTTPS checks passed for a native weather call, a proof supplied
through its tool result, repeated result reuse, SSE cancellation followed by
arithmetic, and 768-dimensional embeddings. All three resident models remained
available.

## Build, check and enable

Use the initialized JetPack 5 Xavier checkout and existing model artifacts from
the [current benchmark procedure](xavier_current_benchmarks.md). Stop the service
before compilation or standalone inference; restore it even if a check fails.

```sh
source scripts/xavier/env.sh
trap 'sudo systemctl start mlc-nemotron' EXIT
sudo systemctl stop mlc-nemotron
cmake --build build -j2

# Supply the exact-token prompt fixture generated by bench_xavier_current.py.
python scripts/check_dflash_prefix.py --cache disable \
  --prompts "$prompt_fixture" --output /tmp/dflash-uncached.json
python scripts/check_dflash_prefix.py --cache radix \
  --prompts "$prompt_fixture" --output /tmp/dflash-cached.json \
  --reference /tmp/dflash-uncached.json
```

For the long conversation regression, export two OpenAI tool-chat payloads into
a JSON list. Keep that fixture private if it contains local instructions or
documents. Replay it in each mode while inference remains stopped:

```sh
python scripts/check_dflash_prefix_conversation.py --cache disable \
  --payloads "$conversation_fixture" --output /tmp/dflash-conversation-uncached.json
python scripts/check_dflash_prefix_conversation.py --cache radix \
  --payloads "$conversation_fixture" --output /tmp/dflash-conversation-cached.json \
  --reference /tmp/dflash-conversation-uncached.json
```

The checker verifies output lengths, prefix hits, reset and matching text. It
drains the synchronous cancellation stream before issuing another request; the
current completion response schema rejects the internal `abort` finish reason.

Set the following in a dedicated `prefix-cache.conf` systemd drop-in for
`mlc-nemotron.service`, then reload systemd and restart the service:

```ini
[Service]
Environment=MLC_NEMOTRON_PREFIX_CACHE=radix
```

To roll back caching, set the variable to `disable` and restart. No model rebuild
or weight conversion is needed. Preserve other service drop-ins.

## Conversation behavior

Reuse requires an identical token prefix. Changed system instructions, tool
definitions or earlier conversation messages reduce the reusable part. A first
request still requires prefill. One recycled sequence also means unrelated users
or requests can evict the previous prefix. Pi's duplicate-evidence filtering and
this cache solve separate costs: prompt growth and repeated computation.

The tool adapter currently omits detailed engine metrics from OpenAI usage, so
Pi may report zero cache-read tokens even when the runtime reuses a prefix.
Tool-enabled responses also remain buffered until the generation completes.
